# PDAce-L: MATLAB Implementations and Numerical Experiments

This repository contains MATLAB implementations and numerical experiments associated with the primal–dual algorithms PDAce-L and aPDAce-L for solving general convex–concave saddle-point problems.

The proposed methods combine convex combination, gradient extrapolation, and adaptive linesearch strategies. The numerical experiments evaluate their computational performance on quadratically constrained quadratic programming (QCQP) problems and convex–concave minimax games (CCMMG).

## 1. Algorithms

The experiments consider the following methods.

**General convex–concave problems**
- **PDAce-L:** Primal–dual algorithm with convex combination, extrapolation, and linesearch.
- **PDAc-L:** Primal–dual algorithm with convex combination and linesearch.
- **PDB:** Primal–dual baseline algorithm with linesearch.

**Strongly convex problems**
- **aPDAce-L:** Accelerated version of PDAce-L.
- **aPDAc-L:** Accelerated version of PDAc-L.
- **APDB:** Accelerated primal–dual algorithm with backtracking.

## 2. Requirements

The numerical experiments are implemented in **MATLAB R2023b**.

The reference computational environment is:

- Operating system: Windows 10 (64-bit)
- Processor: Intel Core i5-10500 @ 3.10 GHz
- Memory: 8 GB RAM

For the QCQP experiments, **CVX with MOSEK** can be used to compute high-accuracy reference solutions for evaluating objective errors.

## 3. Test Problems

### 3.1. Convex QCQP

We consider convex quadratically constrained quadratic programming problems with positive semidefinite quadratic matrices and box constraints.

The experiments compare **PDAce-L, PDAc-L, and PDB**.

The computational performance is evaluated using:

- Number of outer iterations (Iter)
- CPU time in seconds (Time)
- Number of backtracking reductions (#LS)
- Relative objective error
- Constraint violation

To investigate scalability, the experiments consider the problem dimensions

\[
n\in\{100,500,1000\},\qquad
m\in\{10,30,50\}.
\]

The results are summarized using a dimension-dependent comparison table and convergence plots.

### 3.2. Strongly Convex QCQP

Strongly convex QCQP instances are generated by imposing positive definiteness on the quadratic objective matrix.

We compare **aPDAce-L, aPDAc-L, and APDB**, focusing on the convergence behavior of the accelerated algorithms.

The experiments report objective errors and constraint violations against iteration counts and CPU time.

### 3.3. Convex–Concave Minimax Games (CCMMG)

We consider convex–concave minimax games over probability simplices, involving a logistic loss term and a nonlinear convex–concave coupling function.

The experiments compare **PDAce-L, PDAc-L, and PDB**.

Convergence is evaluated using the primal and dual projected fixed-point residuals. The principal test configuration uses

\[
n=100,\qquad m=300.
\]

The numerical results illustrate convergence behavior with respect to both iteration count and CPU time.

## 4. Running the Experiments

1. Clone or download this repository.
2. Open MATLAB R2023b.
3. Set the MATLAB working directory to the repository root.
4. Add the repository and its subdirectories to the MATLAB path using `addpath(genpath(pwd))`.
5. Run the corresponding experiment scripts for convex QCQP, strongly convex QCQP, or CCMMG.

All algorithms should be evaluated using identical problem instances and stopping criteria within each benchmark.

## 5. Numerical Results

The numerical comparisons focus on convergence efficiency and computational cost.

For QCQP, the experiments report objective errors, feasibility violations, iteration counts, CPU time, and backtracking reductions.

For CCMMG, the experiments report projected optimality residuals.

Convergence plots are presented against both iteration counts and CPU time to distinguish iteration efficiency from computational efficiency.

## 6. Reproducibility

The experiments use randomly generated problem instances. For reproducible comparisons, the same generated instances and random seeds should be used across all algorithms.

Algorithmic parameters, stopping tolerances, and maximum iteration limits are specified in the corresponding experimental scripts.
